# GB10（DGX Spark）2 台での学習・評価 runbook

2026-09-22 に用意した、Tailscale 上の GB10 2 台で jqv の学習と評価を回す手順。パスワードはここに書かない（`.env` の `USER` / `PW`、git 未追跡）。

## ホスト

| alias | ホスト名 | Tailscale IP | 直結リンク（両機間、200 GbE） | 役割 |
|---|---|---|---|---|
| `gb10a` | promaxgb10-13fd | 100.99.142.75 | 192.168.200.12 / .16 | 学習（32B） |
| `gb10b` | promaxgb10-1452 | 100.124.156.93 | 192.168.200.13 / .17 | 基準測定・評価 |

共通: NVIDIA GB10、CUDA 13.0（driver 580）、統合メモリ 121 GB、aarch64 Ubuntu 24.04、20 cores、NVMe 3.6 TB。Mac からの RTT は 200〜280 ms。

## 接続

- `~/.ssh/config` に `gb10a` / `gb10b`（User は `.env` の USER、`IdentityFile ~/.ssh/id_ed25519_gb10`、`IdentitiesOnly yes`、`ServerAliveInterval 30`）。
- 鍵 `~/.ssh/id_ed25519_gb10`（パスフレーズなし、この 2 台専用）を両機の `authorized_keys` に登録済み。`ssh -o BatchMode=yes gb10a hostname` で確認。
- パスワードが要る一回きりの操作は `SSH_ASKPASS=<$SSHPASS を echo するスクリプト> SSH_ASKPASS_REQUIRE=force ssh -o PreferredAuthentications=password ...` で行う（`expect` は固まった）。

両機で docker コンテナ `deepseek-v4-flash-vllm-dspark-1`（ghcr.io/anemll/dspark-vllm-gx10:0.1.1、2 台で TP=2 の DeepSeek-V4-Flash）が GPU メモリ 103 GB を使って動いていた。
ユーザーの指示で 2026-09-22 12:35 に両機とも `docker stop` した。戻すときは両機で `docker start deepseek-v4-flash-vllm-dspark-1`（restart policy は変更していない）。

## 初期化（`~/jqv_init.sh`、`tmux` セッション `init`、ログ `~/jqv_init.log`）

1. vLLM 停止、`free -g` で 113 GB 空くことを確認
2. `uv`（`~/.local/bin`）
3. `git clone -b task/hard-family-targeted-lora https://github.com/Octalab-Inc/jqv ~/jqv` → `uv sync`。JevBench ハーネス `~/jevbench`（commit 7ce310c）。
   **注意**: システムの Python 3.12.3 には `Python.h` が無く、CUDA 上で Triton がドライバ拡張をビルドできず全テストが落ちる。
   `uv python install 3.12` の後 `UV_PROJECT_ENVIRONMENT=$HOME/jqv/.venv-managed uv sync --python-preference only-managed` で
   uv 管理の Python（ヘッダ同梱）に環境を作り、以後は `UV_PROJECT_ENVIRONMENT=$HOME/jqv/.venv-managed uv run ...` で実行する（launch スクリプトは設定済み）
4. torch の CUDA 確認: PyPI の `torch 2.14.0+cu130`（aarch64 wheel）がそのまま動いた（`torch.cuda.is_available()` True、arch list に sm_120、GB10 は sm_121 互換）。素の 8192² bf16 matmul で 26〜29 TFLOPS。index の差し替えは不要
5. モデル: サイトの下り回線が合計 5〜8 MB/s しかない（WiFi 上り `wlP9s9` 経由。HF 単一ストリームで 0.7〜1.5 MB/s）ので、A だけで順に取得し
   （1.7B → 32B → 14B、tmux `dl_32b`、ログ `~/dl_32b.log` / `~/dl_14b.log`、終わると `DONE`）、B へは直結リンクで `rsync`（`~/fix_a.sh` が自動で行い、
   B 側の `~/dl_*.log` に `DONE` を書く）。32B（65 GB）は約 2 時間。A → B の鍵は `~/.ssh/id_ed25519`（gb10a-to-b）
6. `uv run python -m jqv.synth.generate --family all`（train を seed 0 + patch から再生成）
7. モデル不要テスト、CUDA での engine 等価性 / isolation テスト（1.7B）

再実行は `ssh gb10a 'tmux new -d -s init "bash ~/jqv_init.sh > ~/jqv_init.log 2>&1"'`（冪等）。

## ジョブの起動と監視

- 長いジョブは必ず tmux 内で、`python -u` と `> ~/<name>.log 2>&1` を付ける。Mac 側は `ssh gb10a 'tail -3 ~/train32.log'` で見る。
- 32B 学習（A、tmux `train32`）:
  `cd ~/jqv && uv run python -u scripts/train_head.py --run-name 32b-hardfam-gb10 --model Qwen/Qwen3-32B --head slot --lora-rank 16 --train-mix "synth:long_policy=0.25,synth:temporal_numeric=0.25,synth:probability=0.2,mmlu=0.3" --val-mix "synth:long_policy:dev=96,synth:temporal_numeric:dev=96,synth:probability:dev=96,mmlu_val=64" --steps 600 --batch-size 8 --grad-accum 4 --grad-checkpointing --max-len 4096 --eval-every 100 --ckpt-every 100 --log-every 10 --brier-weight 0`
- 32B zero-shot 基準（B、tmux `base32`）: `scripts/eval.py --model Qwen/Qwen3-32B --engine packed` を `synth:<family>:test --n 0 --n-val 0`（3 family）、`mmlu --n 1200 --n-val 400`、`jmmlu --n 1200 --n-val 400` で。
- 学習後の評価: `scripts/eval.py --engine slot --head-dir results/train/32b-hardfam-gb10/best`（同じデータセット）→ `fit_temperature.py` → `compare_runs.py --out compare_<name>.json`（results 相対）→ `JEVBENCH_DIR=~/jevbench PYTHONPATH=~/jevbench uv run python scripts/jevbench_run.py --model Qwen/Qwen3-32B --engine slot --head-dir ... --temperature-file ... --label qwen3-32b_hardfam_T --tiers hard` → `jevbench_families.py`。

- JevBench: `scripts/jevbench_run.py` はハーネスの場所を環境変数 `JEVBENCH_DIR` で受ける（既定は Mac のパス）。GB10 では `JEVBENCH_DIR=~/jevbench` を付けないと `harness not found` で止まる（2026-09-22 に B の zero-shot 実行で一度踏んだ）。

## 回収

`rsync -av gb10a:~/jqv/results/train/32b-hardfam-gb10/{best,config.json,train_log.jsonl} results/train/32b-hardfam-gb10/` と
`rsync -av 'gb10a:~/jqv/results/*32b*hardfam*' results/`、`rsync -av gb10a:~/jqv/results/jevbench/qwen3-32b_hardfam_T results/jevbench/`。
記録先は `docs/report.ja.md`。

## 注意

- 2 台は独立に使う（DDP は未実装。設計メモは計画ファイルにある）。
